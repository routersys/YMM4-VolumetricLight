# 体積光 for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-VolumetricLight.svg)](https://github.com/routersys/YMM4-VolumetricLight/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、素材の明るい部分を光源とみなし、画像の面から手前や奥へ伸びる光の筋を、アイテムの3Dの位置と向きに沿って描き、元の映像に重ねる映像エフェクトプラグインです。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
結果は設定と素材の画素とフレームの位置から決まり、乱数は使いません。同じ設定では、同じフレームは何度描いても同じ絵になります。
向き、手前への角度、拡がり、長さ、強さ、しきい値、減衰、光源の大きさ、前方散乱、濃淡、大きさ、流れの速さ、流れの向きの13項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「体積光」と「体積光の遮光」として表示されます。カテゴリは装飾です。

体積光は、空気中の霧や塵に当たった光が散乱して、光の通り道が筋のように見える現象です。3DCGではボリュームライトとも呼ばれます。「体積光」は、この現象を映像として描きます。素材の画像を、光を通す窓のように扱います。画像の面から、「向き」と「手前への角度」で決めた向きへ、画像の矩形を断面とする光の柱が伸びていると考え、画面の各画素から視線に沿って柱の中をたどって、光の筋の明るさを求めます。光の筋の色は素材の画素の色に「色」を掛けたものです。

光の筋は次の順で作ります。

1. 素材の明るさが「しきい値」を超えた分だけを光にします。色合いは変えません。
2. アイテムの位置、回転、拡大率、カメラの設定に従って、光の柱を3Dの空間に置きます。
3. 画面の各画素から視線をたどり、視線が柱を通る区間を細かく区切ります。
4. 区間ごとに、光源の画像の対応する点の光に、「減衰」「前方散乱」「濃淡」と影を掛けて足し合わせます。「光源の大きさ」が大きいほど、遠い区間では光源の画像をぼかして読みます。
5. 「強さ」と「色」を掛け、元の画像に加算で重ねます。

「前方散乱」の見る向きによる明るさの違いには、HenyeyとGreensteinの位相関数を使います。この関数は、Henyey and Greensteinの論文「Diffuse radiation in the Galaxy」（The Astrophysical Journal 93巻、1941年）に基づきます。

「体積光の遮光」は人物などの前景のアイテムに付けるエフェクトです。同じ番号の「体積光」の光の筋を、アイテムの不透明な部分で遮り、光の筋の中に影を落とします。

結果は設定と素材の画素とフレームの位置から決まります。乱数は使いません。同じフレームは何度描いても同じ結果になります。

処理はDirect2Dのカスタムピクセルシェーダーと標準のエフェクトが行います。CPUへの画素の読み戻しは行いません。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-VolumetricLight/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「体積光」を選択してください。影を落とすときは、前景のアイテムに「体積光の遮光」を追加し、「体積光」と同じ番号を選びます。

## 主な機能

### 1. 光源にする部分

「しきい値」は光源にする明るさの下限です。素材の画素の明るさから「しきい値」を引いた分が光になり、色合いは変わりません。上げると明るい部分だけが光源になり、下げると暗い部分も光源になります。0%では素材の全体が光源です。透明な画素は光りません。

「色」は光に掛ける色です。白では素材の画素の色のままになります。

次の画像は、ステンドグラスの窓の写真に適用した例です。「向き」は-60°、「手前への角度」は45°、「強さ」は700%、「しきい値」は30%で、ほかの項目は既定値です。上が入力、下が出力で、しきい値を超える明るいガラスの部分だけが光源になり、窓から右下へ光の筋が伸びます。元の写真は、Wikimedia CommonsにCC0で公開されているWmpearl氏の「[Stained glass window, Hammerfest Church](https://commons.wikimedia.org/wiki/File:Stained_glass_window,_Hammerfest_Church.JPG)」です。

![Image](https://github.com/routersys/YMM4-VolumetricLight/blob/main/docs/VolumetricLight-Window.png)

### 2. 光の向きと広がり

「向き」は、光が進む向きを、画像の面に沿った角度で決めます。0°が右、90°が上、-90°が下です。

「手前への角度」は、光が進む向きの、画像の面からカメラの側への傾きです。正の値で光はカメラの側へ進み、負の値で奥へ進みます。0°に近いほど画像の面に沿って流れ、90°に近いほど画像の面にまっすぐ立ち上がります。絶対値が1°より小さい値は絶対値1°と同じで、89°より大きい値は89°と同じです。

「拡がり」は光の筋の広がり方です。0°では光の筋が平行に進みます。正の値では外へ広がり、負の値では光源より先の一点へ向かって絞られます。絶対値が0.01°より小さい値は0°です。

「長さ」は光の筋の長さです。画像の面から、光が進む向きに沿って測ります。0pxでは光の筋を描かず、映像をそのまま通します。

### 3. 光の筋の見え方

「強さ」は光の筋の明るさです。0%では光の筋を描きません。

「減衰」は光の筋が先端へ向かって弱まる形です。どの値でも、光の筋は先端で消えます。0%では先端へ向かって直線的に弱まり、100%に近いほど光源の近くで急に弱まります。99%より大きい値は99%と同じです。

「光源の大きさ」は光源の見かけの大きさを角度で表した値です。大きいほど、光の筋の縁が先へ向かってぼやけます。

「前方散乱」は光が進む向きへ散乱する強さです。正の値では光源の方を見る向きで光の筋が明るくなり、負の値では光源を背にする向きで明るくなります。0%では見る向きによる明るさの差がありません。

### 4. 塵による濃淡

「濃淡」は光の筋の中を漂う塵のように、光の筋に濃い所と薄い所を付けます。0%では濃淡が付かず、光の筋は一様です。100%ではいちばん薄い所で光がなくなり、いちばん濃い所で明るさが2倍になります。

濃淡は光の筋の中の位置から決まり、奥行きの方向にも変わります。「大きさ」は濃淡のむらの大きさ、「流れの速さ」と「流れの向き」は、むらが画像の面に沿って動く速さと向きです。「流れの速さ」が0px/sのときは、むらは動きません。

「シード値」はむらの形を決める値です。「濃淡」が0%のときは、「シード値」を変えても結果は変わりません。

### 5. アイテムの位置と回転

「体積光」はアイテムの位置、回転、拡大率、反転と、カメラの設定を読んで、光の柱を3Dの空間に置きます。アイテムのX・Y・Zの位置、回転、カメラを変えると、光の筋の見える向きと遠近も一緒に変わります。

このエフェクトはそれらの設定を映像に反映したあと、初期の値に戻して後ろのエフェクトへ渡します。

### 6. 元の画像の表示と品質

「元の画像を表示」がONのときは、光源にした画像も光の筋と一緒に表示します。OFFにすると、光の筋だけを描きます。

「品質」は光の筋を調べる細かさです。「標準」と「高」は、光の筋を縦横それぞれ半分の大きさで計算してから拡大します。「高」は「標準」より細かい間隔で調べ、「最高」は等倍で計算して「高」よりさらに細かい間隔で調べる設定です。高くするほど塵のむらや縁が滑らかになりますが、処理は重くなります。

### 7. 影を落とす

前景のアイテムが光源と光の筋の間にあるとき、その影を光の筋に落とせます。

1. 光源にするアイテムに「体積光」を付け、「遮光」グループの「遮光の番号」を1から8のどれかにします。
2. 影を落とすアイテムに「体積光の遮光」を付け、「番号」を同じ値にします。
3. 影を落とすアイテムは「体積光」を付けたアイテムより上のレイヤーに置きます。

影を落とすアイテムは位置と回転と拡大率を持つ平らな画像として扱い、画像の不透明な部分が光を遮ります。光源の画像の各点から出た光の線が、影を落とすアイテムの不透明な部分を通ると、その線の先の光の筋が弱まって影になります。影を落とすアイテムが影を落とすのは、光源の画像と光の筋の間にあるときだけです。

次の画像は、窓の写真の手前にキャラクターを置いた例です。窓の写真には前の画像と同じ設定の「体積光」を付け、「遮光の番号」を1にしました。キャラクターには「体積光の遮光」を付け、「番号」を上は2、下は1にしました。上は番号が違うので影が落ちません。下は番号が同じなので、キャラクターが遮った分だけ、右と下の光の筋が弱まります。

![Image](https://github.com/routersys/YMM4-VolumetricLight/blob/main/docs/VolumetricLight-Shadow.png)

「遮る強さ」は、影を落とすアイテムの不透明な部分が、光をどれだけ遮るかです。アイテムの不透明度も掛かります。100%で光を通さず、0%で遮りません。

同じ番号に付けられる「体積光の遮光」は4つまでです。5つ目以降は影を落としません。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct2Dのカスタムエフェクトを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 光源には現在のフレームの色と不透明度だけを使います。履歴フレーム、外部画像、学習済みモデルも使いません。
- 素材の幅か高さが4096pxを超えるときは、エフェクトを適用せず入力映像を表示します。
- 光の筋は画面に入る範囲だけを計算します。
- 光の筋はこのエフェクトを付けたアイテムのレイヤーに1枚の映像として描きます。奥行きの違うほかのアイテムとの前後は、レイヤーの順で決まります。
- 「体積光の遮光」は番号ごとに4つまで付けられます。番号は1から8までです。
- 影の縁は影を落とすアイテムの画像の縁のままで、ぼかしません。
- 「体積光」と「体積光の遮光」を同じアイテムに付けても、そのアイテム自身の影は落ちません。
- 「体積光の遮光」はそのエフェクトを付けた位置までの設定で決まる位置と画像を使います。後ろに付けたエフェクトが位置や画像を変えても、影には反映されません。アイテムのエフェクトの最後に付けてください。
- 「体積光」と「体積光の遮光」は、同じカメラの設定を使うアイテムの間でだけ、位置が合います。

## 注意事項

- 処理負荷: 光の筋を調べる回数は「品質」、「長さ」、画面に占める光の筋の面積、素材の大きさで決まります。「品質」を上げるか「長さ」を伸ばすと、重くなります。「濃淡」を0%より大きくすると、さらに重くなります。
- 光の筋を描かないとき: 「長さ」が0のときは、映像をそのまま通します。「強さ」が0のときと、光の筋が画面に入らないときは、光の筋の計算を行わず、元の画像だけを表示します。「元の画像を表示」がOFFのときは、透明な映像になります。
- 再現性: 結果は設定と素材の画素とフレームの位置から決まります。乱数は使いません。同じフレームは何度描いても同じ結果になります。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。更新の確認では、更新情報の取得と比較で起きた例外は報告しません。通知の文を組み立てて表示するときに起きた例外は報告し、YMM4へは渡しません。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct2Dのカスタムエフェクトを作成できないときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | manjubox.netとGitHubのどちらへも接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避します。次にYMM4を起動したあと、本プラグインのエフェクトを生成するか、同じくYMM4-Telemetryで報告する別のプラグインが動き始めると、退避した報告を1回の起動で10件まで送り直します。送信も再送も非同期に行うため、通信を待って起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
